## The one-paragraph diagnosis

The pipeline's **input half works** (briefs in → approval → campaigns → cadence steps → action recommendations: 394 runs, 15 campaigns, 69 actions) but the **feedback half has never run on real data**: `engagement_events`, `outcomes`, and `salesforce_leads` all have **0 rows**. That means Action Outcome Measurement, the Adaptive Decision Engine, Opportunity Offer, Salesforce Activities Read-back, and Engagement → WHEN Signals are all live-but-idle — five daily jobs waking up to an empty table. Four separate blockages cause this, and they're all cheap to fix (items 1–4 below). Until they're fixed, no dashboard chart in the "Action & Outcome Loop" section can ever show anything.

## Part 1 — Broken loops (fix these first, in this order)

### 1. GA4 → Engagement Feeder has failed every night since at least June 28 ⚠ NEW FINDING
Executions 459/495/545/618 (28 Jun–1 Jul, nightly at 05:00 SGT) all end in **`Credentials not found`** on the `Query GA4` HTTP node. The Google API credential is no longer attached to that node (deleted, renamed, or lost in a draft/publish cycle — this project has hit silent credential detachment before). The failure is invisible: no error workflow is attached, so nobody is notified.
**Fix:** open workflow `20tIbI4ku7j35dma` → `Query GA4` node → re-select the Google Service Account credential → publish. Then see item 8 (alerting) so this class of failure can't be silent again.

### 2. `tracking_base_url` is empty → every tracked link ever generated points to `https://example.com`
Confirmed live: all 31 pending + 8 executed actions carry `https://example.com?utm_...` URLs. Even with GA4 fixed, no real visit can ever be attributed. This is the single config value blocking the whole measurement loop.
**Fix:** Settings tab of the dashboard (or one `UPDATE app_config`) once the real marketing site URL exists. If no real site will exist during the internship, consider pointing it at a simple landing page you control so the demo loop can close.

### 3. `when_engine_url` is empty → all human rejection feedback is silently dropped
Both Brief and Action Approval Handlers build the WHEN feedback payload, hit `Engine URL set?`, and route to "no" every time. The rejection-reasons taxonomy work (6 reasons, source/engine_logic routing) collects data that never goes anywhere.
**Fix:** set the URL when available. Until then, consider inserting the payload into a `when_feedback_outbox` table instead of dropping it, so feedback collected now can be replayed later. This is a ~1-node change per handler.

### 4. Approved-action emails go to `rep@yourcompany.com` — a placeholder ⚠ THE most salesperson-facing bug
`Send Action to Rep` (Action Approval Handler, live version) still sends to the literal placeholder. This email is the pipeline's actual product for a rep — the outreach draft + tracked link — and it has never reached a human. Known since the 2026-06-27 audit, still unfixed.
**Fix now:** put a real address in. **Fix properly:** add an `account_owner_email` (per campaign or per account) and send to the owning rep; fall back to a default. See Part 4.

### 5. The downstream chain is idle by consequence, not by bug
Outcomes = 0 → Adaptive Decision Engine has never stamped an `adaptive_action` (confirmed: all 56 cadence steps null) → no campaign has ever completed with `goal_met` → Opportunity Offer has never offered (all 15 campaigns `not_offered`) → `salesforce_leads` = 0 → Activities Read-back reads nothing. No fix needed here; fixing 1–4 (plus actually using quick-log for manual signals) brings this whole chain alive. **Suggested demo path:** after fixing 1–4, approve one brief end-to-end, log 2–3 engagement events via quick-log, and let the 06:00→06:15→06:30→06:45 daily chain run once — that single trace proves the entire architecture.

## Part 2 — Correctness bugs found in live workflows

### 6. Brief Approval Handler has no idempotency gate — **FIXED 2026-07-02**
Action and Opportunity handlers both gate on "was this already processed?"; the Brief handler didn't. A double-clicked or replayed approve link created **duplicate campaigns, duplicate cadence steps, and a duplicate Salesforce Campaign**. Found 2026-07-01.
**Fixed:** both decision UPDATEs now guard on `human_approved IS NULL AND notes <> 'Brief rejected'` (so approve-after-reject and reject-after-approve are also blocked), with `Brief Updated?`/`Reject Updated?` IF gates routing zero-row replays to "This brief has already been processed." Verified live: a replayed approve link for already-approved run 408 returned "already processed" and the campaign chain never executed. Publishing this also restored `mode: runOnceForAllItems` on two Code nodes the draft had silently lost, and shed a stray nested-parameters artifact from the active version.

### 7. `Mark Cancelled` has no status guard ⚠ NEW FINDING
`Mark Executed` guards with `AND status <> 'executed'`, but `Mark Cancelled` runs `UPDATE actions SET status='cancelled' WHERE id = …` unconditionally. A reject link clicked *after* an approve (stale email, second reviewer) silently flips an **executed** action to **cancelled**, and the `sync_cadence_step_status` trigger mirrors the corruption into the cadence.
**Fix:** add `AND status = 'recommended'` and route zero-row results to "already processed".

### 8. Nightly failures are invisible — Error Workflow exists but isn't attached
There is an active "Error Workflow" (`rVr68buB9TD3qR5Y`), but the failing GA4 feeder (and, spot-checked, other workflows) don't reference it in their settings — which is exactly why item 1 went unnoticed for 4 nights.
**Fix:** set it as the error workflow on every scheduled workflow (workflow Settings → Error workflow), and have it email/notify + insert into `pipeline_errors` so the dashboard's Error health panel reflects reality.

### 9. HMAC secret rotation has been undone ⚠ NEW FINDING
The 2026-07-01 rotation moved the approval-link secret server-side via the "Sign Link" workflow — but Sign Link crashed under load (6 crashed executions on 1 Jul, webhook calls running 20s–5min before dying), was deactivated, and **the new secret is now hardcoded in both dashboard HTML files again** (confirmed: the embedded value matches live `app_config`). That includes `pipeline-control-tower-shared.html`, the copy intended for sharing. Anyone who can read either file can forge approve/reject links.
**Fix options:** (a) accept the trust model for the prototype, but then treat the "-shared" file as equally sensitive and stop describing the secret as rotated; or (b) fix Sign Link — the crash pattern (long-running webhook, no timely response) suggests it's missing a fast Respond-to-Webhook path; sign in a single Code node and respond immediately. (b) is the only version where sharing the dashboard is safe.

### 10. Supabase RLS advisory (must-know)
Supabase flags **`public.sc_ai_audit_log` with RLS disabled** — fully readable/writable with the anon key. It belongs to the inactive SC-AI Backbone v2 experiment and has 0 rows, so the practical risk is low, but either enable RLS or drop the table with its experiment:
```sql
ALTER TABLE public.sc_ai_audit_log ENABLE ROW LEVEL SECURITY;
```
(Applying that without policies blocks all client access — fine for a table nothing reads.) Also still open from earlier audits: the schema-level default-ACL rule that grants anon full CRUD on every *new* table/view — it has caused the same leak three times and will again on the next view you create.

## Part 4 — Making it useful to a salesperson (the important part)

Today's rep experience, honestly assessed: they receive **one approval email per cadence step per day** (15 active campaigns' worth), each requiring a click; the emails that matter (the approved outreach draft) go to a placeholder address; the dashboard opens on a Briefs queue and offers 7 tabs full of pipeline vocabulary (gate1_score, sync status, correction rate) that a rep never chose to care about; and there's a **46-action approval backlog, 30 of them older than 3 days, oldest from June 25** — clear evidence the human gate is the bottleneck, not the automation. The system currently *creates* work faster than it removes it. Concrete changes, highest leverage first:

### A. Make the rep email the product
One **daily digest** per rep ("Your 3 touches for today") instead of one email per step: contact name + title, the channel, the ready-to-paste draft, the tracked link, and one Approve-all button plus per-item skip. Reps live in their inbox; if this one email is good, the dashboard becomes optional. This is a rework of Cadence Scheduler's email fan-out (aggregate before sending) — no schema change needed.

### B. Approve the campaign, not every step
The current model human-gates **every** step of an 18-template cadence — that's the reverse of "make lives easier"; the Adaptive Decision Engine exists precisely to manage steps autonomously. Change the default: approving the **brief** authorizes the whole cadence; steps auto-execute on schedule; a rep only gets pinged on *exceptions* (adaptive escalation, goal met, zero engagement). Keep per-step approval as an opt-in per template (e.g. only for `phone`/`partner` steps). This one change eliminates ~80% of the clicking and would have prevented the 46-action backlog.

### C. Give stale recommendations an expiry
An "urgent" outreach recommendation from June 25 is now wrong — timing was the whole point of the WHEN engine. Add a nightly rule: recommendations older than, say, 7 days auto-cancel with `rejection_reason='expired'`, and the WHEN feedback payload says so. Keeps the queue honest and trustworthy.

### D. Add a "My Day" default tab
The default view should answer "what do I do in the next 30 minutes?": today's due steps grouped by account, each with draft + contact + one button. Move Briefs/Actions approval queues next; move Dashboard/AI Decisions/Settings behind an "Ops" section. The Account 360 tab is genuinely good pre-call prep — surface a "print/copy summary" on it and reps will use it before every call.

### E. Close the logging loop where reps already are
Nobody has logged a single engagement event (0 rows) — because quick-log.html is a separate file a rep must know about. Three fixes: embed quick-log as a widget in the main dashboard; put a "Log outcome" link directly in the daily digest email (one click = one engagement event, the plumbing already exists via `/webhook/engagement`); and lean on the Salesforce Activities Read-back — reps who log calls in Salesforce anyway will feed the loop for free once Leads start syncing.

### F. Write outcomes back to where reps look
The reserved `actions.salesforce_task_id` column is unused: sync per-action Tasks' status back to Salesforce (or at least the campaign outcome, which already partially exists), so a rep who lives in Salesforce never needs the dashboard to know where an account stands.

### G. Fill the emails with *why*, briefly
The system already stores `channel_reco_reason` and `adaptive_reason`. One sentence of "why this contact, why now, why this channel" in the digest is what converts a rep from "the robot told me to" to trusting the recommendation. The data's there; it's a template change.
