> **2026-06-29: Adaptive Decision Engine (Phase 4).** New standalone workflow, **`tGYW1gMBXQrC3bQ6`**, daily 06:15 — built additive rather than as a modification of Action Outcome Measurement's branches, to avoid regression risk on a live workflow. `Get Recently Measured Steps` (outcomes measured in the last day, `cs.adaptive_action is null`) → `Loop Measured Steps` → per step, `Get Campaign Signal` (remaining pending steps, next step's id/channel, high-touch-used flag, total engagement count) → `Decide Adaptive Action` (Code — pure rule evaluation, builds a raw multi-statement SQL string) → `Apply Adaptive Decision` (Postgres, executes it). Four rules: **stop** (outcome `met` → cancel remaining steps, campaign → `completed`/`completion_reason='goal_met'`), **pause** (zero `engagement_events` → push next step's `scheduled_for` out 7 days), **escalate** (engagement but no conversion + next step on a low-touch channel → bump to `linkedin_connect` or `phone`), **reviewed** (no-op, just stamped). Pause/escalate mutate the *next* step's `scheduled_for`/`action_type` directly, so Cadence Scheduler's existing `status='pending' and scheduled_for <= now()` query picks both up with zero changes to that workflow. After import, reconnect credentials (Postgres, Gmail, AWS S3, OpenAI, Google API)
and re-publish.
